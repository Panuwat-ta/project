# การใช้งาน Alembic (Database Migrations)

Alembic เป็นเครื่องมือสำหรับจัดการการเปลี่ยนแปลงโครงสร้างฐานข้อมูล (Database Migration) ที่ทำงานร่วมกับ SQLAlchemy โดยจะทำหน้าที่คล้ายกับระบบ Version Control (เช่น Git) แต่ใช้สำหรับฐานข้อมูลโดยเฉพาะ

แทนที่เราจะเข้าไปลบ/เพิ่มคอลัมน์ในฐานข้อมูลด้วยคำสั่ง SQL ตรงๆ เราจะใช้ Alembic ในการสร้างไฟล์ประวัติ (Migration Script) เพื่อเก็บว่าเราแก้ไขอะไรไปบ้าง ทำให้ทีมสามารถอัปเดตฐานข้อมูลให้ตรงกันได้ และยังสามารถย้อนกลับ (Downgrade) หากเกิดข้อผิดพลาดได้ด้วย

---

## โครงสร้างที่เกี่ยวข้อง
- **`server/migrations/versions/`** : โฟลเดอร์ที่เก็บไฟล์ประวัติการเปลี่ยนแปลงทั้งหมด แต่ละไฟล์จะมีคำสั่ง `upgrade()` และ `downgrade()`
- **`server/app/db/models.py`** : ไฟล์ที่เก็บโครงสร้างตาราง (Table Schema) ของระบบ
- **`server/alembic.ini`** : ไฟล์ตั้งค่าการทำงานของ Alembic

---

## คำสั่งที่ใช้บ่อย (Workflow)

> **หมายเหตุ:** ต้องรันคำสั่งทั้งหมดนี้ภายในโฟลเดอร์ `server/` และต้องเปิดใช้งาน Virtual Environment (venv) อยู่เสมอ

### 1. สร้างไฟล์ประวัติใหม่ (Generate Migration)
เมื่อมีการแก้ไขโค้ด Model เช่น เพิ่มตาราง เพิ่มคอลัมน์ หรือลบคอลัมน์ ให้รันคำสั่งนี้เพื่อสร้างไฟล์บันทึกการเปลี่ยนแปลง:

```bash
alembic revision --autogenerate -m "คำอธิบายการแก้ไข"
```
**ตัวอย่าง:** `alembic revision --autogenerate -m "add_admin_table"`
*ระบบจะเปรียบเทียบโค้ดในไฟล์ Model กับฐานข้อมูลปัจจุบัน และสร้างไฟล์เวอร์ชันใหม่ขึ้นมาในโฟลเดอร์ `versions/` โดยอัตโนมัติ*

### 2. อัปเดตฐานข้อมูล (Upgrade)
หลังจากสร้างไฟล์ Migration แล้ว โครงสร้างในฐานข้อมูลจริงจะยังไม่เปลี่ยน จนกว่าเราจะสั่งรันคำสั่งนี้:

```bash
alembic upgrade head
```
*คำสั่งนี้จะรันการเปลี่ยนแปลงใหม่ทั้งหมด เพื่อนำไปใช้กับฐานข้อมูลจริง (`head` หมายถึงให้รันไปจนถึงเวอร์ชันล่าสุด)*

### 3. ย้อนกลับการเปลี่ยนแปลง (Downgrade)
ถ้าอัปเดตไปแล้วพบว่ามีปัญหา หรือต้องการยกเลิกการเปลี่ยนแปลงล่าสุด ให้รันคำสั่งนี้:

```bash
alembic downgrade -1
```
*คำสั่งนี้จะย้อนกลับฐานข้อมูลไป 1 สเตป (สามารถระบุเป็น ID ของเวอร์ชันที่ต้องการย้อนกลับไปก็ได้)*

---

## ข้อควรระวัง
- **ตรวจทานไฟล์ก่อน Upgrade เสมอ:** การใช้ `--autogenerate` ระบบอาจไม่สามารถจับการเปลี่ยนแปลงบางอย่างได้ 100% (เช่น การเปลี่ยนชื่อคอลัมน์ ระบบอาจเข้าใจว่าเป็นการลบแล้วสร้างใหม่) จึงควรเปิดไฟล์ใน `versions/` ดูฟังก์ชัน `upgrade()` เสมอก่อนรัน `alembic upgrade head`
- **ห้ามแก้ไขไฟล์ Migration เก่า:** หากไฟล์นั้นถูกรัน (`upgrade`) ไปยังฐานข้อมูลหลักหรือฐานข้อมูลของเพื่อนร่วมทีมแล้ว ห้ามกลับไปแก้ไขไฟล์นั้นเด็ดขาด หากต้องการแก้ไขให้สร้าง Migration ไฟล์ใหม่แทน
