# Project Scope 

**Project Name:** แอปตรวจสอบรูปภาพตัดต่อที่ถูกนำมาหลอกลวง (Scam Image Detection)  
**Version:** 1.0  
**Date:** August 23, 2026

---

## 1. Scope Overview

ระบบ ScamGuard ถูกออกแบบเป็นระบบตรวจสอบความเสี่ยงของรูปภาพที่อาจถูกปลอมแปลงหรือใช้เพื่อการหลอกลวง โดยแบ่งการทำงานออกเป็น **4 ขอบเขตหลัก (Scope Areas)** ที่ครอบคลุมตั้งแต่ส่วนหน้าบ้าน (Frontend) สำหรับผู้ใช้ทั่วไป, ระบบหลังบ้าน (Backend) ที่ทำหน้าที่ประสานงานและวิเคราะห์ข้อมูล, เครื่องมือวิเคราะห์ปัญญาประดิษฐ์ (AI Inference Engine), และหน้าเว็บควบคุมสำหรับผู้ดูแลระบบ (Admin Web Portal)

ระบบดำเนินการวิเคราะห์ภาพผ่านกระบวนการแบบหลายชั้น (Multi-layer Analysis):
1. **Textual Analysis** — วิเคราะห์ข้อความในภาพด้วย OCR และตรวจจับคำสำคัญหลอกลวง
2. **Visual Analysis** — ตรวจสอบการตัดต่อระดับพิกเซลและภาพที่สร้างด้วย AI
3. **Source Analysis** — ค้นหาแหล่งที่มาของภาพผ่าน Reverse Image Search

ผลลัพธ์สุดท้ายเป็น **คะแนนความเสี่ยงรวม (Weighted Risk Score)** ในช่วง 0-100 พร้อมระดับความเสี่ยง (Low/Medium/High) และแผนที่ความร้อน (Grad-CAM Heatmap) เพื่ออธิบายผลการตัดสินใจของ AI

## 2. In Scope

### SC01 — ระบบแอปพลิเคชันสำหรับผู้ใช้ทั่วไป (General User Mobile App)

**Scope ID:** SC01  
**Name:** ระบบแอปพลิเคชันสำหรับผู้ใช้ทั่วไป (General User Mobile App)  
**Platform:** Android (พัฒนาด้วย Flutter)

**Description:**  
พัฒนาแอปพลิเคชันบนมือถือสำหรับผู้ใช้งานทั่วไป โดยรองรับการทำงานบน Android อย่างเต็มประสิทธิภาพ ครอบคลุมฟังก์ชันตั้งแต่การสมัครสมาชิก การเข้าสู่ระบบ การนำเข้ารูปภาพ การแสดงผลความเสี่ยง การจัดเก็บประวัติ และการรายงานภาพหลอกลวง

**Related Stakeholders:** ST01 (ผู้ใช้งานทั่วไป), ST02 (ผู้ดูแลระบบ - ในส่วนของการรับรายงาน)

**Related Objectives:** OBJ-01, OBJ-04

**Key Components:**

1. **ระบบลงทะเบียนและยืนยันตัวตน (Authentication)**
   - สมัครสมาชิกด้วย Email และ Password พร้อมการยืนยันความถูกต้องของข้อมูล
   - เข้าสู่ระบบด้วย Email/Password หรือ Social OAuth (Google Login / Apple ID)
   - ระบบกู้คืนรหัสผ่าน (Forgot Password)
   - จัดเก็บ Token ใน Secure Storage และรักษาสถานะการเข้าสู่ระบบ

2. **ระบบนำเข้ารูปภาพ (Image Input Module)**
   - เลือกรูปภาพจากคลังภาพ (Gallery) ของอุปกรณ์
   - รองรับรูปแบบไฟล์: JPG/JPEG, PNG, WebP
   - ระบบครอบตัดรูปภาพ (Image Cropper) ก่อนส่งตรวจสอบ
   - ระบบตรวจสอบขนาดไฟล์และความละเอียดของภาพก่อนอัปโหลด

3. **ระบบแสดงผลความเสี่ยง (Risk Visualization Dashboard)**
   - แสดงคะแนนความเสี่ยงรวม (Weighted Risk Score 0-100) ในรูปแบบ Radial Gauge
   - แสดงระดับความเสี่ยง (Risk Grade): Low (สีเขียว), Medium (สีเหลือง), High (สีแดง)
   - แสดงรายละเอียดผลวิเคราะห์แบบหลายชั้น:
     - Text Risk Score: ผลตรวจสอบ OCR และคำสำคัญหลอกลวง
     - Visual Risk Score: ผลตรวจสอบการตัดต่อและภาพ AI-Generated
     - Source Risk Score: ผลตรวจสอบแหล่งที่มา (Reverse Image Search)
   - แสดงภาพแผนที่ความร้อน (Grad-CAM Heatmap) ที่ระบุจุดผิดปกติ
   - สามารถสลับระหว่างภาพต้นฉบับและภาพ Heatmap ได้

4. **ระบบจัดการประวัติและนโยบายความเป็นส่วนตัว (History & PDPA Control)**
   - แสดงรายการประวัติการสแกนย้อนหลัง พร้อม thumbnail, วันที่, คะแนนความเสี่ยง
   - ค้นหาและกรองประวัติตามระดับความเสี่ยงและวันที่
   - ลบประวัติทีละรายการ (Slide to delete) หรือลบทั้งหมด
   - หน้ายินยอมการเข้าถึงข้อมูล (Consent Screen) แบบ 2 ระดับ:
     - System Consent: ยินยอมให้ระบบประมวลผลภาพ (บังคับ)
     - Research Consent: ยินยอมให้นำข้อมูลไปใช้วิจัย (ไม่บังคับ, สามารถถอนได้)
   - ผู้ใช้สามารถเข้าถึงและจัดการความยินยอมได้ตลอดเวลา

5. **ระบบรายงานและแชร์ข้อมูล (Community Report & Notification)**
   - ปุ่มรายงานภาพหลอกลวง (Scam Report Button) พร้อมระบุหมวดหมู่และคำอธิบาย
   - ระบบแชร์ภาพผลลัพธ์และคำเตือนภัยไปยังแอปพลิเคชันภายนอก (Share via LINE, Facebook, etc.)
   - รับการแจ้งเตือนผ่าน Firebase Cloud Messaging (FCM) เมื่อระบบประมวลผลเสร็จสิ้น

**Expected Outcome:**
- แอปพลิเคชันบนมือถือที่ใช้งานง่าย สะดวก และให้ผลลัพธ์ที่เข้าใจได้
- ผู้ใช้สามารถตรวจสอบรูปภาพที่น่าสงสัยได้ภายในเวลาไม่เกิน 15 วินาที (กรณีวิเคราะห์ใหม่)
- ผู้ใช้เข้าใจผลการวิเคราะห์ผ่าน Heatmap โดยไม่ต้องมีความรู้ทางเทคนิค

### SC02 — ระบบ API หลังบ้านและส่วนเชื่อมต่อภายนอก (API Backend & Integrations)

**Scope ID:** SC02  
**Name:** ระบบ API หลังบ้านและส่วนเชื่อมต่อภายนอก (API Backend & Integrations)  
**Technology:** Python FastAPI

**Description:**  
พัฒนาระบบ API หลังบ้านที่ทำหน้าที่เป็นศูนย์กลางประมวลผลและประสานงาน (Orchestrator) ระหว่างแอปพลิเคชัน, เซิร์ฟเวอร์ AI และบริการภายนอก รองรับการทำงานแบบ Asynchronous เพื่อประสิทธิภาพสูงสุด

**Related Stakeholders:** ST01, ST02

**Related Objectives:** OBJ-03, OBJ-04

**Key Components:**

1. **งานพัฒนา API Core & Gateway (FastAPI)**
   - ระบบ Routing ปลอดภัย รองรับโปรโตคอล HTTPS/TLS
   - ระบบยืนยันตัวตนระดับ Token (JWT Authentication) พร้อม Access Token และ Refresh Token
   - ระบบควบคุมอัตราการเรียกใช้ API (Rate Limiting) ป้องกันการโจมตี DDoS และ Bot
   - API Documentation อัตโนมัติผ่าน OpenAPI (Swagger UI)

2. **งานพัฒนาโมดูลสกัดข้อความและการวิเคราะห์ประโยค (OCR & Textual Analysis)**
   - สกัดตัวอักษรไทย-อังกฤษจากรูปภาพด้วยเทคโนโลยี Surya-OCR (GGUF/Qwen2.5-VL)
   - ตรวจจับชุดคำค้นอันตราย (Scam Keywords) เช่น "กู้เงินด่วน", "ถอนยอด", "โบนัสพิเศษ", "ด่วน", "รับเงิน", "ลงทุน" ด้วย RegEx และ NLP
   - คำนวณ Text Risk Score (0-100) จากจำนวนและความรุนแรงของคำหลอกลวงที่พบ

3. **งานพัฒนาสกัดข้อมูลแฝงและการค้นหาภาพย้อนกลับ (Metadata & Reverse Image Search)**
   - สกัดข้อมูล EXIF/GPS Metadata เพื่อตรวจสอบรุ่นอุปกรณ์, วันที่ถ่าย, และพิกัดที่บันทึกไว้
   - เชื่อมต่อ Google Vision API สำหรับค้นหาภาพย้อนกลับ (Reverse Image Search)
   - ตรวจสอบความถี่การปรากฏของภาพบนอินเทอร์เน็ต เพื่อประเมินว่าเป็นภาพที่ถูกคัดลอกหรือแอบอ้าง
   - คำนวณ Source Risk Score (0-100) จากจำนวนและบริบทของแหล่งที่พบ

4. **งานพัฒนาฐานข้อมูลหลักและแคช (PostgreSQL & Redis Cache)**
   - ออกแบบ Database Schema สำหรับจัดเก็บ:
     - ข้อมูลผู้ใช้งาน (Users table) พร้อม Role และ Status
     - ประวัติการตรวจสอบ (Scans table) พร้อมคะแนนและผลลัพธ์
     - บันทึกรายงานสแกมเมอร์ (Reports table)
     - Audit Logs สำหรับการดำเนินการของ Admin
     - Consent Logs สำหรับบันทึกความยินยอม (PDPA)
   - พัฒนา Logic ระบบแคช (Redis) เก็บค่า Image Hash เพื่อ:
     - ลดเวลาตอบสนอง (Cache Hit ≤ 3 วินาที)
     - ลดการใช้ทรัพยากร GPU/CPU จากการรัน AI ซ้ำ
   - จัดเก็บไฟล์รูปภาพและ Heatmap บน Cloud Storage พร้อม URL แบบ Presigned

**Expected Outcome:**
- ระบบ API ที่มีประสิทธิภาพสูง รองรับการทำงานแบบ Concurrent
- การตอบสนองเร็ว (Cache Hit ≤ 3 วินาที, New Analysis ≤ 15 วินาที)
- ความปลอดภัยสูง (HTTPS, JWT, Rate Limiting)
- ระบบจัดเก็บข้อมูลที่มีความสมบูรณ์และตรวจสอบย้อนกลับได้

### SC03 — บริการตรวจจับภาพตัดต่อและปัญญาประดิษฐ์ (AI Inference Engine)

**Scope ID:** SC03  
**Name:** บริการตรวจจับภาพตัดต่อและปัญญาประดิษฐ์ (AI Inference Engine)  
**Technology:** PyTorch / ONNX Runtime

**Description:**  
พัฒนาส่วนประมวลผลโมเดล Deep Learning สำหรับวิเคราะห์รูปภาพในระดับพิกเซล แยกคอนเทนเนอร์ทำงานอิสระเพื่อรองรับการขยายตัว (Scalability) และไม่กระทบต่อประสิทธิภาพของ API Gateway

**Related Stakeholders:** ST01, ST02, ST03

**Related Objectives:** OBJ-02, OBJ-04

**Key Components:**

1. **งานวิจัยและคัดกรองชุดข้อมูลฝึกสอน (Scam Dataset Preparation)**
   - รวบรวมสลิปโอนเงินปลอม, ภาพบุคคลตัดต่อ, และรูปภาพที่สร้างจาก Generative AI
   - จัดทำป้ายกำกับพิกเซล (Pixel-level Annotations) ในส่วนที่ถูกแก้ไข
   - สร้างชุดข้อมูลบริบทไทย (Thai-Context Scam Dataset) จากการรายงานของผู้ใช้จริง
   - แบ่งข้อมูลเป็น Training Set (70%), Validation Set (15%), Testing Set (15%)

2. **งานพัฒนาโมดูลตรวจสอบร่องรอยการดัดแปลงภาพ (Image Forgery Detection)**
   - พัฒนาโมดูลคำนวณ Error Level Analysis (ELA) เพื่อตรวจหาการบีบอัดซ้ำ (Re-compression)
   - พัฒนาโมเดล Deep Learning (PSCC-Net + SegFormer) เพื่อ:
     - ตรวจจับการคัดลอกและวาง (Copy-Move)
     - ตรวจจับการสอดแทรก (Splicing)
     - ตรวจจับการลบวัตถุ (Inpainting)
   - เป้าหมายความแม่นยำ: Accuracy และ F1-Score ≥ 85%

3. **งานพัฒนาโมดูลตรวจสอบภาพสังเคราะห์จากปัญญาประดิษฐ์ (AI-Generated Image Detection)**
   - พัฒนาโมเดลตรวจหา Artifacts ที่หลงเหลือจาก Generative AI
   - ตรวจจับลักษณะทางฟิสิกส์ผิดปกติ เช่น:
     - ความไม่สมมาตรของใบหน้า
     - ข้อมือหรือนิ้วมือที่ผิดปกติ
     - พื้นหลังที่ไม่สอดคล้องกับแหล่งกำเนิดแสง
   - รองรับการตรวจจับภาพจาก DALL-E, Midjourney, Stable Diffusion

4. **งานพัฒนาเซอร์วิสประมวลผลและการอธิบายโมเดล (AI Inference & Explainability)**
   - พัฒนาส่วนควบคุมการรับไฟล์และประมวลผล (PyTorch Backend Service)
   - แปลงโมเดลเป็น ONNX format เพื่อเพิ่มความเร็ว Inference 2-5 เท่า
   - สร้างแผนที่ความร้อน Grad-CAM (Gradient-weighted Class Activation Mapping)
   - คำนวณ Visual Risk Score (0-100) จากผลลัพธ์ของทั้ง 2 โมเดล

**Expected Outcome:**
- โมเดล AI มีความแม่นยำ ≥ 85% (Accuracy และ F1-Score)
- ความเร็ว Inference เฉลี่ย ≤ 10 วินาทีต่อภาพ (บน GPU)
- แผนที่ความร้อนที่ชัดเจน ช่วยให้ผู้ใช้เข้าใจผลการวิเคราะห์
- โมเดลสามารถ Deploy และ Scale ได้อิสระจาก API Gateway

### SC04 — หน้าเว็บควบคุมสำหรับผู้ดูแลระบบ (Admin Web Portal)

**Scope ID:** SC04  
**Name:** หน้าเว็บควบคุมสำหรับผู้ดูแลระบบ (Admin Web Portal)  
**Technology:** React.js + Tailwind CSS

**Description:**  
พัฒนาหน้าเว็บแสดงสถิติและควบคุมความปลอดภัยของระบบสำหรับทีมผู้ดูแลระบบและนักวิจัย รองรับการจัดการผู้ใช้ ตรวจสอบรายงาน จัดการชุดข้อมูล และอัปเดตโมเดล AI

**Related Stakeholders:** ST02 (ผู้ดูแลระบบ), ST03 (อาจารย์ที่ปรึกษา - สำหรับตรวจสอบสถิติ)

**Related Objectives:** OBJ-04

**Key Components:**

1. **งานพัฒนาระบบควบคุมสิทธิ์ผู้ดูแลระบบ (Dashboard & RBAC)**
   - หน้ายืนยันตัวตนสำหรับผู้ดูแลระบบแยกจากผู้ใช้ทั่วไป
   - ระบบควบคุมสิทธิ์ตามบทบาท (Role-Based Access Control - RBAC):
     - Admin: สิทธิ์เต็มในการจัดการทุกส่วน
     - Moderator: สิทธิ์ตรวจสอบรายงานและจัดการผู้ใช้
     - Viewer: สิทธิ์ดูสถิติเท่านั้น
   - หน้ารายงานสถิติภาพรวม (Statistical Dashboard):
     - จำนวนผู้ใช้งานทั้งหมดและผู้ใช้งานรายวัน/รายเดือน
     - จำนวนการสแกนทั้งหมดและการกระจายตามระดับความเสี่ยง (Low/Medium/High)
     - ความแม่นยำของโมเดล AI (Accuracy Metrics)
     - อัตราสัดส่วน Cache Hit vs New Analysis
     - สถิติการรายงานตามหมวดหมู่

2. **งานพัฒนาระบบตรวจสอบรายงานประวัติการสแกม (Scam Reports Queue)**
   - หน้าดึงรูปภาพที่ผู้ใช้รายงานส่งเข้ามา (Report List Queue)
   - ระบุสถานะรายงาน: Pending, Reviewing, Approved, Rejected
   - Admin สามารถ:
     - ดูรายละเอียดรายงาน พร้อมรูปภาพและผลวิเคราะห์
     - อนุมัติ (Approve) รายงาน เพื่อนำเข้าชุดข้อมูลวิจัย
     - ปฏิเสธ (Reject) รายงาน พร้อมระบุเหตุผล (Admin Note)
   - หน้าประวัติการทำงานของผู้ดูแลระบบ (Audit Logs):
     - บันทึกทุกคำสั่ง: การอนุมัติ/ปฏิเสธรายงาน, การเปลี่ยนสิทธิ์ผู้ใช้, การอัปเดตโมเดล
     - ระบุผู้ทำ, เวลา, และรายละเอียดการกระทำ
     - ไม่สามารถแก้ไขหรือลบ Audit Logs ได้ (Immutable)

3. **งานพัฒนาระบบอัปเดตโมเดลและความยืดหยุ่น (Model Update Module)**
   - หน้าดูรายการโมเดล AI ทั้งหมด พร้อมเวอร์ชัน วันที่ Deploy และสถานะ (Active/Inactive)
   - อัปโหลดไฟล์น้ำหนักโมเดล (Model Weights .onnx) เวอร์ชันใหม่
   - เปิดใช้งานโมเดลเวอร์ชันใหม่ (Activate) โดยระบบจะปิดเวอร์ชันเก่าอัตโนมัติ
   - ส่งออกชุดข้อมูลรูปภาพที่ได้รับการอนุมัติ (Export Approved Dataset) สำหรับการฝึกสอนโมเดลเพิ่มเติม
   - ดาวน์โหลดรายงานประสิทธิภาพโมเดล (Model Performance Report)

**Expected Outcome:**
- แดชบอร์ดที่แสดงสถิติครบถ้วนและเข้าใจง่าย
- กระบวนการตรวจสอบรายงานที่มีประสิทธิภาพและโปร่งใส
- ระบบอัปเดตโมเดลที่ปลอดภัยและไม่กระทบต่อการใช้งานของผู้ใช้
- Audit Logs ที่สมบูรณ์เพื่อความโปร่งใสและการตรวจสอบย้อนกลับ

## 3. Out of Scope

สิ่งที่ระบบ **ไม่ครอบคลุม** ในเวอร์ชัน 1.0 (Baseline):

### 3.1 แพลตฟอร์มที่ไม่รองรับ
- **iOS Application:** รุ่นแรกมุ่งเน้นที่ Android เท่านั้น การพัฒนาเวอร์ชัน iOS อยู่ในแผนอนาคต
- **Web Application สำหรับผู้ใช้ทั่วไป:** ผู้ใช้ทั่วไปต้องใช้แอปมือถือเท่านั้น ไม่มีเวอร์ชันเว็บ
- **Desktop Application:** ไม่มีการพัฒนาแอปพลิเคชันสำหรับ Windows, macOS, หรือ Linux

### 3.2 ประเภทไฟล์ที่ไม่รองรับ
- **วิดีโอ:** ระบบตรวจสอบเฉพาะภาพนิ่งเท่านั้น ไม่รองรับการวิเคราะห์วิดีโอ (Video Deepfake Detection)
- **ไฟล์เสียง:** ไม่มีการวิเคราะห์ไฟล์เสียงหรือ Voice Cloning Detection
- **เอกสาร PDF/Word:** ระบบไม่ตรวจสอบเอกสารที่ไม่ใช่ภาพ

### 3.3 ฟังก์ชันที่ไม่อยู่ในขอบเขต
- **On-Device AI Inference:** การประมวลผล AI ทั้งหมดเกิดที่เซิร์ฟเวอร์ ไม่มี On-Device Model
- **Real-time Camera Analysis:** ไม่มีการวิเคราะห์แบบ Real-time ผ่านกล้อง ต้องบันทึกภาพก่อน
- **Automated Legal Action:** ระบบไม่แจ้งหน่วยงานภายนอก (ตำรวจ, ธนาคาร) โดยอัตโนมัติ
- **Financial Transaction Verification:** ไม่เชื่อมต่อกับธนาคารเพื่อยืนยันการทำธุรกรรมจริง
- **Identity Verification:** ไม่มีการยืนยันตัวตนบุคคลในภาพ (Face Recognition)
- **Content Moderation:** ไม่ตรวจสอบเนื้อหาที่ไม่เหมาะสม (Inappropriate Content Detection)

### 3.4 การรับประกันและข้อจำกัดทางกฎหมาย
- **ไม่ใช่หลักฐานทางนิติวิทยาศาสตร์:** ผลการวิเคราะห์เป็นการประเมินเบื้องต้นเท่านั้น ไม่สามารถใช้เป็นพยานหลักฐานในชั้นศาลได้โดยตรง
- **ไม่รับประกันความแม่นยำ 100%:** โมเดล AI อาจมีข้อผิดพลาด (False Positive / False Negative)
- **ไม่ให้คำแนะนำทางกฎหมาย:** ระบบไม่ให้คำปรึกษาทางกฎหมาย การเงิน หรือการลงทุน

## 4. Scope Boundaries

### 4.1 System Responsibilities (สิ่งที่ระบบทำ)

1. **รับและตรวจสอบไฟล์ภาพ:** รับไฟล์ภาพจากผู้ใช้ ตรวจสอบความถูกต้อง ขนาด และรูปแบบ
2. **วิเคราะห์แบบหลายมิติ:** ดำเนินการวิเคราะห์ Textual, Visual และ Source Analysis
3. **คำนวณคะแนนความเสี่ยง:** รวมคะแนนจากทุกชั้นการวิเคราะห์เป็นคะแนนรวมตามสูตรที่กำหนด
4. **สร้างคำอธิบาย:** สร้างแผนที่ความร้อน (Heatmap) และคำอธิบายที่เข้าใจง่าย
5. **จัดเก็บผลลัพธ์:** บันทึกผลการวิเคราะห์ลงฐานข้อมูลพร้อม Timestamp
6. **แจ้งเตือนผู้ใช้:** ส่งการแจ้งเตือนผ่าน FCM เมื่อการวิเคราะห์เสร็จสิ้น
7. **รักษาความเป็นส่วนตัว:** ปฏิบัติตามหลัก PDPA และจัดการความยินยอมของผู้ใช้

### 4.2 User Responsibilities (สิ่งที่ผู้ใช้ต้องทำ)

1. **เตรียมรูปภาพ:** เลือกรูปภาพที่ต้องการตรวจสอบจากอุปกรณ์
2. **ให้ความยินยอม:** อ่านและยอมรับเงื่อนไขการใช้งานและนโยบายความเป็นส่วนตัว
3. **ตีความผลลัพธ์:** ใช้วิจารณญาณร่วมกับผลการวิเคราะห์ในการตัดสินใจ
4. **รายงานที่ถูกต้อง:** รายงานเฉพาะภาพที่มีเหตุผลเชื่อว่าเป็นภาพหลอกลวงจริง
5. **รักษาความปลอดภัย:** รักษา Account และ Password ไม่ให้ผู้อื่นเข้าถึง

### 4.3 External System Responsibilities (สิ่งที่ระบบภายนอกทำ)

1. **Google Vision API:** ค้นหาแหล่งที่มาของภาพบนอินเทอร์เน็ต
2. **Firebase Cloud Messaging:** ส่งการแจ้งเตือนไปยังอุปกรณ์ของผู้ใช้
3. **Cloud Storage Provider:** จัดเก็บไฟล์รูปภาพและ Heatmap อย่างปลอดภัย

## 7. Document Summary

เอกสาร Project Scope ฉบับนี้กำหนดขอบเขตการพัฒนาระบบ ScamGuard อย่างชัดเจน โดยแบ่งเป็น **4 ขอบเขตหลัก (SC01-SC04)** ครอบคลุม:

1. **SC01 — Mobile App:** แอปพลิเคชันสำหรับผู้ใช้ทั่วไป (Flutter, Android)
2. **SC02 — API Backend:** ระบบหลังบ้านและการเชื่อมต่อ (FastAPI, PostgreSQL, Redis)
3. **SC03 — AI Inference:** บริการวิเคราะห์ปัญญาประดิษฐ์ (PyTorch, ONNX)
4. **SC04 — Admin Portal:** หน้าเว็บสำหรับผู้ดูแลระบบ (React, Tailwind CSS)

ระบบทำงานผ่านกระบวนการ **Multi-layer Analysis** (Textual, Visual, Source) และส่งผลลัพธ์เป็น **Risk Score** พร้อม **Heatmap** เพื่อความโปร่งใส

เอกสารนี้ระบุชัดเจนว่าอะไร **อยู่ในขอบเขต (In Scope)** และอะไร **ไม่อยู่ในขอบเขต (Out of Scope)** เพื่อให้ทุกฝ่ายเข้าใจตรงกัน
