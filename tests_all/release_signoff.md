## 1. วิธีใช้เช็กลิสต์นี้

1. กรอกข้อมูลเวอร์ชันในหัวข้อที่ 2 ทุกครั้งที่ขอปล่อย 1 รอบต่อ 1 ไฟล์ย่อยหรือ 1 ชุดต่อท้ายพร้อมวันที่ ห้ามเขียนทับรอบเก่า
2. ตรวจทีละข้อในหัวข้อที่ 3 ถ้าข้อใดไม่ผ่าน ห้ามลงนาม ให้ส่งกลับไป Retest หรือ Regression ก่อน
3. นำตัวเลข Pass Rate มาจาก execution_log.md และรายงาน automate จริงเท่านั้น ห้ามใช้ตัวเลขจากการอ่านเอกสาร
4. รายการ GAP และ Deferred ในหัวข้อที่ 5 ต้องตรงกับ rtm.md ถ้าพบ GAP ใหม่ต้องบันทึกเพิ่มและให้ PM รับทราบ
5. ลงนามครบ 3 ฝ่ายในหัวข้อที่ 6 จึงถือว่าปล่อยได้ ถ้าฝ่ายใดไม่ลงนามให้ระบุเหตุผลและเงื่อนไขค้าง

## 3. เกณฑ์ออกจากแผนหลัก (Exit Criteria ตรวจทีละข้อ ตรงตามแผนหลักส่วนที่ 5.3)

- ข้อ 1: TC ระดับ P0 Blocker และ P1 High ผ่าน 100 เปอร์เซ็นต์ (Pass Rate เท่ากับ 100)
  - ผลจริง P0: ผ่านกี่ TC จากทั้งหมดกี่ TC
  - ผลจริง P1: ผ่านกี่ TC จากทั้งหมดกี่ TC
  - ผ่านเกณฑ์หรือไม่: ผ่าน หรือ ไม่ผ่าน
- ข้อ 2: TC ระดับ P2 Medium ผ่านไม่ต่ำกว่า 95 เปอร์เซ็นต์
  - ผลจริง P2: ผ่านกี่ TC จากทั้งหมดกี่ TC คิดเป็นกี่เปอร์เซ็นต์
  - ผ่านเกณฑ์หรือไม่: ผ่าน หรือ ไม่ผ่าน
- ข้อ 3: ไม่มีข้อบกพร่องคงค้างระดับ Critical หรือ Major (0 Open Critical Bugs ตามแผนหลัก และ Major ต้องไม่ค้างเช่นกัน)
  - จำนวน Bug ค้างระดับ Critical: ระบุจำนวนและเลข Bug ถ้ามี
  - จำนวน Bug ค้างระดับ Major: ระบุจำนวนและเลข Bug ถ้ามี
  - ผ่านเกณฑ์หรือไม่: ผ่าน หรือ ไม่ผ่าน
- ข้อ 4: เวลาตอบสนองจาก Locust ผ่านเกณฑ์ Cache Hit P50 ≤1.5s / P95 ≤3.0s และ Full Inference P50 ≤15s / P95 ≤25s / P99 ≤35s (PARETO เดียวกับ TC-NFR-PERF-01/02 และแผนหลัก)
  - ผลจริง Cache Hit P50/P95: ระบุกี่วินาที
  - ผลจริง Full Inference P50/P95/P99: ระบุกี่วินาที
  - ผ่านเกณฑ์หรือไม่: ผ่าน หรือ ไม่ผ่าน
- ข้อ 5: ตารางสอบย้อนกลับครอบคลุม FR และ NFR ทั้งหมด FR ใดยังไม่มี TC ให้ระบุ GAP หรือ Deferred ชัดเจน
  - อ้างอิง rtm.md ฉบับวันที่ใช้ตรวจ: ระบุเวอร์ชันและวันที่
  - รายการ GAP/Deferred ตรงกับหัวข้อที่ 5 ของไฟล์นี้หรือไม่: ตรง หรือ ไม่ตรง

## 4. ความครอบคลุมขั้นต่ำ (Coverage ขั้นต่ำ อ้างอิง rtm.md ฉบับ Baseline 150 TCs v1.3.1)

- NFR 17 รายการ (รวม NFR-COMP-01/02): Covered 15 รายการ คิดเป็น 88.2 เปอร์เซ็นต์, นับรวม Partial 17 รายการ คิดเป็น 100 เปอร์เซ็นต์

- เกณฑ์ขั้นต่ำสำหรับลงนามรอบนี้:

## 5. รายการ GAP และ Deferred ที่ยอมรับได้ (ต้องตรงกับ rtm.md)

- GAP 4 รายการ (ยังไม่มี TC — ตรงกับ rtm.md §4):
  1. FR-SYS-01 ดึง EXIF และ Metadata: ยอมรับหรือไม่ยอมรับ พร้อมเหตุผลและแผน (เช่น เลื่อนเป็น Phase ถัดไป)
  2. FR-SYS-04 Reverse Image Search: ยอมรับหรือไม่ยอมรับ พร้อมเหตุผลและแผน
  3. FR-SYS-06 คัดกรองภาพสังเคราะห์ Generative AI: ยอมรับหรือไม่ยอมรับ พร้อมเหตุผลและแผน
  4. FR-SHARE-01 แชร์ผลลัพธ์ไปแอปภายนอก: ยอมรับหรือไม่ยอมรับ พร้อมเหตุผลและแผน
- Deferred 2 รายการ (มี TC แต่รอทำ Phase 2):
  1. FR-AUTH-06 Google OAuth: ยอมรับการเลื่อนหรือไม่ พร้อมเงื่อนไข (เช่น ห้ามอ้างว่ารองรับ OAuth ในเอกสารปล่อย)
  2. FR-SYS-10 FCM Push Notification (TC-MOB-NOTIF-01, TC-NFR-FCM-01): ยอมรับการเลื่อนหรือไม่ พร้อมเงื่อนไข
- Partial ที่ต้องรับทราบความเสี่ยง 7 รายการ FR และ 2 รายการ NFR ตามหัวข้อที่ 4: ระบุทีละรายการว่ายอมรับหรือต้องแก้ก่อนปล่อย
- GAP ใหม่ที่พบนอกเหนือ rtm.md (ถ้ามี): ระบุ Requirement ID, TC ที่เกี่ยวข้อง, เหตุผล (เช่น เส้น cancelScan ไม่มี endpoint, category keys ไม่ตรงกัน, key safe ตกค้าง) และผู้รับทราบ

- ปล่อยได้โดยไม่มีเงื่อนไข: Exit Criteria ผ่านทุกข้อ และไม่มี GAP ใหม่
