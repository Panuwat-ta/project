# การออกแบบการเทรนโมเดล (Model Training Design)
## โครงงาน: แอปตรวจสอบรูปภาพตัดต่อที่ถูกนำมาหลอกลวง (Scam Image Detection)

เอกสารฉบับนี้อธิบายถึงสถาปัตยกรรมและกลยุทธ์ในการเทรนโมเดล AI สำหรับตรวจจับภาพหลอกลวง ตั้งแต่แนวคิดพื้นฐาน การเทรนเบื้องต้น การนำไปใช้งาน (Inference) และการเทรนเพิ่มเติมแบบออนไลน์

---

## 1. แนวคิดหลัก: การแช่แข็งน้ำหนักเดิม 100% (Freeze Backbone / Feature Extractor)

เพื่อให้การเทรนโมเดลใช้ทรัพยากรน้อยลง ทำได้รวดเร็ว และป้องกันปัญหา Catastrophic Forgetting (การลืมความรู้เดิมของโมเดล) สถาปัตยกรรมจะถูกแบ่งออกเป็น 2 ส่วนหลัก:

1. **Backbone / Feature Extractor (แช่แข็ง 100%)**:
   - เป็นส่วนที่ใช้ในการสกัดคุณลักษณะ (Feature Extraction) จากรูปภาพ เช่น ขอบ, พื้นผิว, โครงสร้าง (เช่น ใช้ ResNet, EfficientNet, หรือ Vision Transformer)
   - น้ำหนัก (Weights) ของชั้นเลเยอร์เหล่านี้จะถูกตั้งค่าให้ไม่สามารถเปลี่ยนค่าได้ในระหว่างการเทรน (`requires_grad = False`)
   - หน้าที่คือการแปลงรูปภาพอินพุตให้อยู่ในรูปแบบของเวกเตอร์คุณลักษณะ (Feature Vectors/Embeddings) ที่มีคุณภาพสูง

2. **Classification Head (ส่วนที่ใช้เทรน)**:
   - เป็นชั้นเลเยอร์ Fully Connected (Dense Layers) ที่ต่อท้ายจาก Backbone
   - น้ำหนักของส่วนนี้จะถูกอนุญาตให้อัปเดตได้ (Trainable) เพื่อเรียนรู้การจำแนกประเภท (Classification) ว่าเวกเตอร์ที่ได้มานั้นเป็นภาพปกติ หรือภาพสแกม

---

## 2. ขั้นตอนการเทรนโมเดลเริ่มต้น (Initial Training Phase)

- **การเตรียมสถาปัตยกรรม**: โหลดโมเดลที่ผ่านการ Pre-trained (เช่น จาก ImageNet หรือชุดข้อมูลภาพตัดต่อขนาดใหญ่)
- **การแช่แข็ง (Freezing)**: ทำการวนลูปผ่านทุกพารามิเตอร์ใน Backbone และตั้งค่าให้ปิดการคำนวณ Gradient
- **การปรับแต่ง (Fine-Tuning Head)**: เทรนเฉพาะส่วน Classification Head ด้วยชุดข้อมูลภาพ Scam และภาพปกติที่เตรียมไว้
- **การส่งออก (Export)**: หลังจากเทรนเสร็จสิ้น บันทึกน้ำหนักของโมเดล (ส่วน Backbone ที่ถูกแช่แข็ง + Head ที่ถูกเทรนใหม่) ในรูปแบบที่พร้อมใช้งาน (เช่น `.onnx` หรือ `.pt`)

---

## 3. การออกแบบระบบเทรนโมเดลเพิ่มเติมผ่าน Admin Page (Incremental Training)

เพื่อรับมือกับรูปแบบการหลอกลวงหรือ Scam ประเภทใหม่ๆ ที่เกิดขึ้นอย่างต่อเนื่อง ระบบ Admin Page จึงถูกออกแบบให้สามารถอัปเดตความรู้ของโมเดลได้ โดยไม่ต้องเทรนโมเดลใหม่ทั้งหมดตั้งแต่ต้น

### 3.1 การทำงานฝั่ง Admin Page (UI/UX Workflow)
1. **การรวบรวมข้อมูล**: แอดมินตรวจสอบรูปภาพที่ผู้ใช้รายงาน (Scam Reports) และติดป้ายกำกับ (Label) ว่าเป็นภาพสแกมประเภทใหม่
2. **หน้าจอ Model Retraining**: แอดมินไปที่หน้าเมนู "เทรนโมเดลเพิ่มเติม" ซึ่งจะแสดงจำนวนรูปภาพใหม่ที่พร้อมสำหรับนำไปเทรน
3. **สั่งรันการเทรน (Trigger Training)**: เมื่อกดปุ่มเทรน ระบบหน้าบ้านจะส่ง API Request ไปยัง Backend พร้อมส่งคำสั่งให้เริ่มการเทรนโมเดลเพิ่มเติม

### 3.2 กระบวนการทำงานฝั่ง Backend & AI Inference Service
เมื่อได้รับคำสั่งจาก Admin Page ระบบเซิร์ฟเวอร์จะดำเนินการดังนี้:

1. **ดึงข้อมูล (Data Fetching)**: ดึงรูปภาพใหม่และภาพตัวอย่างเดิมบางส่วนจากฐานข้อมูล เพื่อสร้าง Mini-batch ป้องกันปัญหาโมเดลเอนเอียง (Data Imbalance)
2. **การสกัดคุณลักษณะ (Feature Extraction)**:
   - นำภาพเข้าสู่ **Backbone ที่ถูกแช่แข็งไว้ 100%** เพื่อแปลงเป็น Feature Vectors (ขั้นตอนนี้รวดเร็วมาก เพราะไม่มีการคำนวณ Gradient ย้อนกลับ)
3. **การเทรนเพิ่มเติม (Classifier Fine-Tuning)**:
   - นำ Feature Vectors ที่ได้ มาเทรนอัปเดตค่าน้ำหนักเฉพาะชั้น **Classification Head** 
   - ใช้ Learning Rate ที่ต่ำมาก (เช่น `1e-4` หรือ `1e-5`) เพื่อค่อยๆ ปรับปรุงน้ำหนักโดยไม่ทำลายความรู้เดิม
4. **การประเมินผล (Validation)**: นำโมเดลที่เทรน Head เสร็จแล้วไปทดสอบกับ Validation Set ว่าค่าความแม่นยำ (Accuracy / F1-Score) ยังคงดีอยู่และไม่แย่ลง
5. **การสลับใช้งาน (Hot Swap / Zero Downtime)**:
   - หากผลการประเมินผ่านเกณฑ์ ระบบจะทำการบันทึกโมเดลเวอร์ชันใหม่
   - ส่งสัญญาณ (Signal) แจ้ง AI Inference Service ให้โหลดน้ำหนักโมเดลใหม่เข้าสู่หน่วยความจำ (Hot Reload) ทันที โดยที่ผู้ใช้งานระบบทั่วไปจะไม่รู้สึกถึงการหยุดชะงัก

### 3.3 ข้อดีของแนวทางนี้
- **รวดเร็ว**: ใช้เวลาเทรนน้อยกว่าการเทรนใหม่ทั้งโมเดลหลายเท่าตัว เพราะ Backpropagate เกิดขึ้นแค่ส่วนท้ายของเครือข่าย
- **ประหยัดทรัพยากร**: สามารถเทรนบนเซิร์ฟเวอร์ที่มี GPU ขนาดเล็ก หรือแม้แต่ CPU ก็สามารถทำงานได้
- **ปรับตัวได้ไว**: ตอบสนองต่อเทรนด์ของสแกมเมอร์ได้ทันท่วงทีผ่านปลายนิ้วของแอดมิน

## 4. การออกแบบ AI Inference Service (PyTorch / ONNX Runtime)

เพื่อให้กระบวนการรันโมเดล Deep Learning มีความเร็วสูงสุดและสามารถสเกลเซิร์ฟเวอร์แยกต่างหากได้ ระบบจึงใช้ ONNX Runtime (C++ Core Execution Engine) ในการรันโมเดลที่แปลงมาจาก PyTorch

### 4.1 ท่อประมวลผลและการอธิบายภาพ (AI Inference Pipeline)
1. **ภาพนำเข้า (Preprocessed Tensor):** รูปภาพจะถูกปรับขนาดเป็น 512x512 พิกเซล และนอร์มัลไลซ์ค่าสีตามข้อกำหนดของอินพุตโมเดล
2. **โมดูลวิเคราะห์พิกเซลและการตัดต่อ (Visual Forgery Detection):**
   * รันโมเดล PSCC-Net เพื่อดึงคุณลักษณะความสอดคล้องเชิงพื้นที่และช่องสี (Spatio-Channel Correlation) ระบุพื้นที่และขอบเขตที่น่าสงสัยว่าจะถูกดัดแปลง
   * รันโมเดล SegFormer เพื่อสร้าง Pixel-level Segmentation Mask จำแนกรอบพิกเซลดัดแปลงที่มีความสมบูรณ์และลดสัญญาณรบกวนขอบ
   * รวมผลลัพธ์ของโมเดลทั้งสองและสร้างเป็น Pixel Anomaly Map
3. **โมดูลตรวจวิเคราะห์รูปภาพจากปัญญาประดิษฐ์ (AI-Generated Image Detection):**
   * ใช้ลักษณนามแบบ Deep Learning Classifier ตรวจสอบเศษซากทางสถิติพิกเซลและความถี่ของสี (Artifacts) ที่เกิดขึ้นจากการเจเนอเรตภาพ
4. **การแสดงผลอธิบายเหตุผลของ AI (Explainable AI - XAI):**
   * ประมวลผลสร้างแผนภูมิความร้อน (Grad-CAM Heatmap / Anomaly Heatmap) นำสีระดับความเสี่ยง (สีแดงเข้มถึงสีน้ำเงิน) ไปวางซ้อนทับภาพจริง เพื่อแสดงขอบเขตของการตัดต่อตัวเลขหรือข้อมูลบนสลิป/รูปภาพอย่างชัดเจน

### 4.2 ระบบสลับและอัปเดตโมเดลเวอร์ชันใหม่ (Dynamic Model Weights Update)
* เซิร์ฟเวอร์ AI จะมีฟังก์ชันโหลดโมเดลใหม่โดยไม่ต้องหยุดการทำงานของเซิร์ฟเวอร์ (Zero-downtime hot reloading)
* เมื่อแอดมินอัปโหลดไฟล์น้ำหนักโมเดลเวอร์ชันใหม่ผ่าน Admin Portal (.onnx format) ระบบหลังบ้านจะเซฟไฟล์ลงไดเรกทอรีของโมเดล และส่งคำสั่งแจ้งเซิร์ฟเวอร์ AI ให้เคลียร์เซสชันหน่วยความจำและรันโหลดโหลดน้ำหนักโมเดลไฟล์ใหม่เข้าสู่ ONNX Runtime Session ทันที
